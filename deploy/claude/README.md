# Hermes on Claude Code

Since 2026-10, Hermes's brain is headless Claude Code (`claude -p`) on Tristan's Claude subscriptions, replacing hermes-agent. hermes-agent lost its last provider on 2026-08-03: subscription logins used by third-party apps are billed as extra usage, and putting a subscription token into hermes-agent is against Anthropic's consumer terms. Claude Code itself running on the subscription is first-party use.

The vault side is unchanged: obsidian-ops, the livesync bridge, the hourly vault snapshots, the vault layout under `Hermes/`.

## How it runs

| Job | Trigger | Model |
|---|---|---|
| chat | `hermes-claude-telegram.service` long-polls @Hermes_secretarybot; one conversation is resumed until 8 h idle | Sonnet |
| briefing | `hermes-claude-briefing.timer`, Mon–Fri 06:30 Europe/Berlin (DST-proof) | Opus |
| commands | `hermes-claude-commands.timer`, every 5 min; Claude starts only when `pending_commands` is non-empty | Sonnet |

Models are set in `~/hermes-claude/hermes.env` (`HERMES_MODEL_*`).

**Accounts.** Every session goes through `bin/claude_accounts.py`, a copy of nxguide's `hosting/loop/duxloop/claude_accounts.py` (keep them in sync). It picks the first account not parked at its usage limit, parks one that hits its limit until the reset its message names, and resumes the same session on the next account. The accounts are the `CLAUDE_ACCOUNT_TOKENS` entries of every file in `HERMES_ACCOUNT_FILES`, merged in order in memory:

1. `~/duxloop-watch/secrets/claude.env`: the duxloop watcher's Duxalpha1 and Duxalpha2, read in place so that no second copy of those tokens exists.
2. `~/hermes-claude/secrets/accounts.env`: accounts only Hermes uses (`work`), written by `add-claude-account.sh`.

When every account is parked, chat answers with the reset time, commands wait, and the briefing tells Tristan and schedules its own retry.

**What the model can touch.** No shell, no file access (`.claude/settings.json`, `--permission-mode dontAsk`). Its tools are web search/fetch and the `hermes` MCP server (`bin/hermes_mcp.py`):

- `vault_read`/`vault_write`: obsidian-ops endpoints from an allowlist. The approval secret is added server-side, so the model never sees it.
- `telegram_send`: Tristan's chat only.
- `remember`: appends to `memory/lessons.md`, which `CLAUDE.md` imports into every session.
- `chat_history`: the Telegram log in `state/chat.jsonl`.

Secrets (`TELEGRAM_BOT_TOKEN`, `OBSIDIAN_APPROVAL_SECRET`) are read by key from `~/.hermes/.env` and `~/.hermes/obsidian.env` where they already are.

**Failures are loud.** A job that cannot work (vault API down, no account left, Claude error) messages Tristan directly, without the model; repeats of the same alert are held back for 6 h, except briefing failures.

## Install / update

On the VM, from the repo checkout:

```bash
deploy/claude/install.sh            # files, config, units; memory/state/secrets are kept
deploy/claude/install.sh --enable   # also stops hermes-gateway/dashboard, starts the three units
~/hermes-claude/bin/hermes_run.py check   # needs hermes.env in the environment, see below
```

Run anything by hand with the units' environment:

```bash
set -a; . ~/hermes-claude/hermes.env; set +a
python3 ~/hermes-claude/bin/hermes_run.py check      # one Haiku turn per account
systemctl --user start hermes-claude-briefing         # a briefing now
journalctl --user -u 'hermes-claude-*' -f
```

## Adding or renewing an account

Setup-tokens last a year. Tristan runs, in their own terminal:

```bash
ssh -t nxguide-dev-cloud ~/hermes-claude/bin/add-claude-account.sh work
```

`claude setup-token` runs, they sign in in the browser and paste the code, and the script lifts the token from the terminal transcript, checks it with one Haiku turn and writes it to `secrets/accounts.env`. It never echoes the token or puts it on a command line, and it shreds the transcript. To un-park an account early, delete its key from `state/claude_accounts.json`.

## Layout on the VM

```text
~/hermes-claude/
  CLAUDE.md, VAULT.md, prompts/   persona, vault manual, job prompts (from this repo)
  .claude/settings.json           permissions
  mcp.json, hermes.env            generated by install.sh
  bin/                            the scripts in deploy/claude/bin
  memory/lessons.md               Hermes's memory (kept across installs)
  state/                          chat log, chat session, offsets, parked accounts, alerts
  secrets/accounts.env            Hermes-only account tokens (mode 600)
  .claude-home/                   CLAUDE_CONFIG_DIR: Hermes's sessions, apart from the watcher's
```
